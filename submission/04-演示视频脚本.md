## 一、拍摄前要准备好的东西（开机前逐项打勾）

### 1. 启动演示环境（终端操作，**全车间模式**）

```bash
cd 项目根目录
FJSP_MHS_MACHINES="M-01 M-02 M-03 M-04 M-05 M-06 M-07 M-08" bash scripts/start-demo.sh
```

> 业务服务本次新增了工件实时位置接口（`GET /orders/{ref}/position`），start-demo.sh 检测到源码新于 jar 会**自动重新打包**，无需手工构建。

等到终端打印「演示环境已启动」，确认 3 个入口都能打开：

| 入口 | 地址 | 拍摄中用途 |

### 2. 重置演示数据 + 清空经验库（保证和证据包一致）

```bash
bash scripts/reset-demo.sh -y
rm -f ~/.agh/fjsp-experience.jsonl
```

- 看到「演示数据重置完成」即可。**重置后不要再乱点页面上的写操作**，否则视频里的编号（EVT、PV、TSK）会和证据对不上。
- 第二行清空 RSI 处置经验库：视频第 3 段要演示「第一次处置，经验库为空」，第 4 段才能演示「第二次同类故障，命中经验推荐」。**漏删经验库，第 3 段的口播就不成立。**

### 3. 刷新 AGH 插件与技能（本次新增能力，必做）

fjsp-tools 插件新增了 `fjsp_get_gantt_link`（排程后给甘特图链接）和 `fjsp_get_workpiece_position`（查工件实时位置）两个工具，技能规程 SKILL.md 也已更新。**插件从不可变快照运行，改了代码必须重装**，否则新工具不会出现：

```bash
cd agh-integration
A="node agnes-harness/packages/cli/dist/local/agnes.mjs"
$A package disable @fjsp/fjsp-tools
$A package remove @fjsp/fjsp-tools
$A package inspect file:./fjsp-tools        # 记下输出的 integrity
(sleep 3; echo y; sleep 2) | script -q /dev/null $A install file:./fjsp-tools
$A package trust @fjsp/fjsp-tools <上一步 integrity> e3de4e5f2da4b8aa2650af5c4f822d397c2dadd7a6695e5071c0444d26a22b01
$A package enable @fjsp/fjsp-tools
$A package status                            # 期望 desired=enabled actual=running trusted=true
cp skills/fjsp-dispatch/SKILL.md ~/.agh/skills/fjsp-dispatch/SKILL.md
$A skills refresh --root-key user-agnes
```

> 甘特图链接的前端地址由 `scripts/demo-common.sh` 自动推导注入（`FJSP_WEB_BASE`）。**若 AGH daemon 是复用的旧进程，该环境变量不会生效**——`bash scripts/stop-demo.sh` 后用第 1 步命令整体重启。

### 第 3 段 故障扰动处置与经验首记（01:15–02:10，55 秒）

- 【画面窗口】标签 2（AGH 工作台）→ 标签 1（前端验收）。**不切换账号**。
- 【逐步操作】
  1. 在 AGH 工作台**再新建一个会话**（避免上一段上下文干扰；新会话同样确认工作区/权限/模型三个开关）；
  2. 粘贴这句话发送（时间规则见下方说明，务必按录制当天 reset 结果重算）：
     ```
     M-03 设备 2026-10-11 22:37 发生故障，预计维修 2 小时，帮我处置
     ```
     > **故障时间换算规则**：演示数据采用 RELATIVE 模式，每次 `reset-demo.sh` 会把仿真起点锚定为重置时刻（reset 输出里的 `simulationStartAt`）。故障时间 = `simulationStartAt + 30 小时`，维修 120 分钟——该偏移量对应证据包中「落在 M-03 可用班次窗口、零扰动」的原始场景（2026-09-16 08:00 起点 + 30h = 09-17 14:00）。上例按 2026-10-10 16:37 重置算得 2026-10-11 22:37；录制当天 reset 后重新加 30 小时即可。
  3. 预期画面：Agent 调 `fjsp_report_breakdown` 登记故障（**弹审批，点「批准」**），返回事件号 EVT-xxx；
  4. **新增镜头（RSI 铺垫，别漏）**：Agent 调 `fjsp_experience_query` 查询处置经验库——返回「经验库为空，无推荐」，随后按默认策略调 `fjsp_reschedule` 选择 **LOCAL 局部重调度**（**弹审批，点「批准」**）。把「经验查询 → 无记录 → 走默认策略」这一小段拍清楚；
  5. Agent 轮询 `fjsp_task_status` 到 **FEASIBLE**；
  6. Agent 主动调 `fjsp_compare_plans`（只读，无审批）；
  7. 预期画面（主线，本次录制实际走向）：模型给出量化对比结论——「故障压在 M-03 的加工窗口上，局部重调度后 C_max 从 49.8h 延至 54.2h、加权拖期 +52h，机器分配零变更、仅 0.5% 工序顺序微调，建议评审后发布新方案」。**结论停屏 5 秒**；
     > **可能的分支（零扰动）**：如果模型结论变成「故障落在空闲窗口、零扰动、无需发布」，直接停在这里即可，第 9 步的版本页验收改为「LOCAL 版本未发布、当前发布计划不变」，口播相应换成「……这说明 Agnes 模型不只是机械执行，更能基于数据做出可解释的决策判断」；
  8. 在同一会话回复 `评审通过并发布`，Agent 调 `fjsp_approve_review`（**弹审批点批准**）→ `fjsp_publish`（**再弹审批点批准**）→ 新方案 PUBLISHED；
  9. **新增镜头（经验沉淀）**：发布后 Agent 自动调 `fjsp_experience_record` 把本次处置（事件类型、重调度模式、KPI 差值、是否发布）写入经验库（**弹审批点批准**）。把这一步拍清楚，第 4 段的 RSI 闭环靠它铺垫；
  10. **回前端验收**：切到标签 1，「事件管理 → 设备故障」，事件记录列表里出现刚登记的 EVT-xxx（BREAKDOWN / M-03）；再点「计划调度 → 计划版本」——局部重调度版本为「当前发布 / 已发布」，基线版本自动转为「**已替代**」且行尾出现「**回滚**」入口（状态流转 + 可回滚，各停 2 秒）。
- 【口播】（约 260 字）

> 接下来演示动态扰动处置。设备 M-03 明晚发生故障，我直接告诉智能体故障时间和预计维修时长。注意这里：模型先查询了处置经验库——这是系统第一次遇到这类事件，库里没有记录，于是按默认策略选择局部重调度，只调整受影响的工序，机器分配一个都不动。重调度可行之后，模型主动调用方案对比给出量化结论，提交评审后主动停下，由我确认发布。最后一步很关键：模型把这次处置的模式和 KPI 结果沉淀进了经验库。回到业务系统可以看到：新方案已成为当前发布版本，旧基线自动转为已替代，并且随时可以一键回滚。

## 三、现场问题速查

| 情况 | 怎么办 |
|------|--------|
| AGH 发送按钮灰色、消息发不出去 | 输入框下方三个开关没选全：工作区选 `agh-integration`（Desktop 路径，别选 Documents 旧副本）、权限保持 `Changes within the workspace`、模型选 `agnes-3.0-flash`，选齐后按钮变蓝 |
| Devices 面板只有 1 台设备 | 启动时没带全车间参数：`FJSP_MHS_MACHINES="M-01 ... M-08" bash scripts/start-demo.sh`；或设备进程是旧的，`bash scripts/stop-demo.sh` 后重启 |
| 设备卡片没有状态面板画面 | 设备进程的 Python 环境缺 Pillow：重建 `mhs-devices/.venv` 并 `pip install jsonschema websockets pillow`，重启设备进程 |
| 第 3 段 Agent 查经验库时返回了推荐 | 经验库没清空：`rm -f ~/.agh/fjsp-experience.jsonl`，并重录第 3、4 段 |
| 发布失败 `E_PLAN_STALE` | 方案快照之后又录入了新事件，计划按设计过期、不可发布。改走更新的事件催生的最新版本（提交评审 → 通过 → 发布）；过期版本可驳回清理 |
| 「发布成功」但页面状态不变 | 大概率你看的是**旧版本**的详情页——发布成功的是最新版本。点左侧审批队列 / 计划版本列表切到最新版本号确认状态流转，调度看板顶部也会显示新的当前发布 |
| AGH 审批弹窗没出现 | 确认指令里涉及写操作；若 Agent 直接执行了，说明该工具是只读（如看板/对比/经验查询），属正常 |
| Agent 录故障返回 `E_DUPLICATE` | 设计内行为：与已有维修区间重叠。回复 `选 A` 走完全重调度 |
| Agent 不出甘特图链接 / 查不了工件位置 | 插件快照未刷新：按准备清单第 3 步重装 fjsp-tools 并刷新技能（改插件代码后必须 disable→remove→install→trust→enable） |
| 甘特图链接打开空白或端口不对 | AGH daemon 是复用的旧进程，`FJSP_WEB_BASE` 没生效：`bash scripts/stop-demo.sh` 后用第 1 步命令整体重启 |
| 工件位置查询报「当前没有已发布计划」 | 第 6 段之前必须先完成第 2 段的排程与发布 |
| 模拟器报「无法连接业务服务」/「请先排程发布」 | 确认 8081 业务服务在跑且已有 PUBLISHED 计划；个别工序 4xx 报错模拟器会打印并跳过，属正常 |
| Agent 回答的设备与前端页面对不上 | 模拟器在持续推进，答案随时间变化属正常；追问一次对齐最新状态 |
| 任务长时间不到 FEASIBLE | 别停录，继续等；超过 3 分钟就停录，查 `业务服务/算法服务`日志后重拍该段 |
| watch 超过 40 秒没唤醒 | 先确认故障已注入：`kill -0 $(cat "${TMPDIR:-/tmp}/fjsp-demo/m03.pid)"` 进程在不在；必要时重新 `kill -USR1` |
| 点错按钮 / 说错话 | 不用整段重来：该段重录，后期剪接。**但若涉及写操作（建基线/录事件/发布），必须重置数据（并清经验库）后从头跑该段** |
| 画面录进了敏感信息 | AGH 的「Provider 设置」页不要入镜；`.env`、终端里 export Key 的历史不要入镜（演示密码 `Fj@123456` 可以入镜） |

## 四、录制与上传建议

- **录制工具**：macOS 用 QuickTime Player 屏幕录制或 OBS Studio；1080p，开启鼠标点击高亮。
