## 复现步骤

### 1. 解压 ZIP

```bash
unzip 组别-参赛编号-队伍名称-队长姓名.zip -d fjsp
cd fjsp
```

### 2. 安装依赖（一次性）

```bash
pip install -r algorithm-service/requirements.txt
cd web-vue && npm install && npm run build && cd ..
cd agh-integration && python3 -m venv mhs-devices/.venv && mhs-devices/.venv/bin/pip install jsonschema websockets pillow && cd ..
cp .env.example .env
# 编辑 .env，设置 FJSP_DB_PASSWORD（数据库密码）
```

### 3. 一键启动

```bash
bash scripts/start-demo.sh
```

默认依次拉起：PostgreSQL（Docker Compose）→ 算法服务（8101）→ 业务服务（8081）→ 前端（8082）。AGH 工作台和 MHS 设备默认不启动；完成下文 AGH CLI 构建与配置后，使用 `FJSP_START_AGH=1 bash scripts/start-demo.sh` 启动工作台（4177）。启用时脚本会选用 Node ≥ 24、拉起 daemon 和 AgnesHub（4180）；MHS 默认只起 M-03，`FJSP_MHS_MACHINES="M-01 M-02 M-03 M-04 M-05 M-06 M-07 M-08"` 可起 8 台，`FJSP_START_MHS=0` 可关闭设备。

仅体验业务系统时无需 Agnes API Key；AGH/MHS 为可选的额外复现步骤。

### 4. 访问入口

| 入口 | 地址 |
|------|------|
| 前端界面 | `http://127.0.0.1:8082/index.html?api=http://localhost:8081/api/v1` |
| 业务 API | `http://localhost:8081/api/v1` |
| 算法服务 | `http://localhost:8101` |
| AGH 工作台 | `http://localhost:4177` |
| AgnesHub Devices 面板 | `http://127.0.0.1:4180` |

### 5. 验证运行

```bash
# 算法服务健康检查
curl http://localhost:8101/health

# 前端字段契约 E2E（401→登录→reset→建基线→轮询→版本分页，逐接口断言）
node scripts/e2e-api-check.mjs

# 业务全流程冒烟（基线→审核→发布→故障/插单→重调度→并发发布→执行反馈→审计校验）
bash business-service/scripts/smoke-test.sh

# 基础数据写接口正/负例
bash scripts/crud-check.sh

# 算法服务单元测试（本次 61 通过、1 个 slow 跳过）
cd algorithm-service && python3 -m pytest

# 业务服务测试（42 个单元测试类 + 12 个 Testcontainers 集成测试类，集成测试需 Docker）
cd business-service && mvn test
```

算法服务自带演示算例 `demo_instance.json`（20 订单 / 8 设备），无需额外准备数据即可复现排程结果。

## AGH 智能体部分（可选）

AGH 部分需要 Agnes API Key，**提交包已随附评审专用 Key**（`agh-integration/agnes.env`），评审方无需自备：

0. ZIP 中的 `agh-integration/agnes-harness/` 是源码快照（不含 node_modules 与构建产物），先构建一次：
   ```bash
   cd agh-integration/agnes-harness
   corepack enable pnpm && pnpm install        # 需要 Node ≥ 24.10
   pnpm --filter @agnes/cli build:local        # 产出 packages/cli/dist/local/agnes.mjs
   pnpm --filter @agnes/mhs build:plugin       # 仅 MHS 设备接入需要：产出 AgnesHub 插件
   ```
   构建完成后按 `agh-integration/README.md` 完成 fjsp-tools 插件与 `@agnes/mhs` 插件的 install/trust/enable（install 需真实终端确认，README 中有伪终端绕行写法）；
1. 按 `agh-integration/README.md` 执行 AGH CLI config 向导，Provider 选 **Agnes AI**，网关 `https://api.agnes-ai.cn/v1`，模型 `agnes-3.0-flash`；
2. 凭据就位：执行 `mkdir -p ~/.config/fjsp && cp agh-integration/agnes.env ~/.config/fjsp/agnes.env`（评审专用 Key 已随包附带，该 Key 仅授权 agnes-3.0-flash、仅中国区网关可用）；
3. 启动 AGH 工作台（4177）后，即可用中文指令驱动，例如「帮我完成基线排程并发布」「M-03 发生故障，请处置」；
4. 无 Key 时保持默认 `FJSP_START_AGH=0`，系统其余功能不受影响。

### MHS 设备接入（可选，无需真实硬件）

在 AGH 已运行的基础上，可体验"设备异常自动上报 → Agent 被唤醒处置"的设备接入链路：

1. 启用 AgnesHub 插件并启动虚拟机床设备（步骤见 `agh-integration/README.md` 的「MHS 设备接入」一节），Hub 监听 `127.0.0.1:4180`，工作台右侧出现 Devices 面板：8 台机床在线（全车间模式）、每台带状态面板画面，World 标签为车间布局地图；
2. 在 AGH 对话中下达「盯着 cnc-m03（对应 M-03），温度越限或停机就按故障流程处置」；
3. 对设备进程 `kill -USR1` 注入故障（或 `touch /tmp/m03-fault`），约 20 秒内温度越限触发唤醒，Agent 自动确认读数、录入故障事件、重调度、提交评审并逐步请求人工审批；`kill -USR2` 恢复设备正常；
4. 处置结束 Agent 会把结果沉淀到处置经验库（`~/.agh/fjsp-experience.jsonl`）；再发一次同类故障指令，可看到它查询经验库并引用历史最优策略（RSI 闭环，端到端证据见 `agh-integration/evidence/agh-rsi-*.jsonl`）。
