## 2. 完整工具/设备调用链（≥1 条）

以 `agh-verify-1` 为例，一条中文指令「帮我完成基线排程并发布」产生的完整调用链：

```
用户中文指令
  → Agnes 模型（agnes-3.0-flash，经 AGH）
    → fjsp_dashboard            [READ，免审批]      查询看板
    → fjsp_create_baseline      [WRITE，审批通过]   创建基线排程任务
    → fjsp_task_status          [READ，免审批]      轮询至 FEASIBLE
    → fjsp_publish              [HIGH_RISK，审批通过] 发布方案
  → 业务系统落库：PV-001 状态 = PUBLISHED
  → 模型输出中文 KPI 报告：
      makespan 3112 分钟、加权拖期 38908、拖期 14/20、负载不均衡度 0.0832
```

两次写操作（create_baseline、publish）的审批事件均记录在 jsonl 账本中，与业务侧审计记录（`X-Source: agh` 透传落库）互相印证。

## 3. Agnes 模型参与核心任务的证据点

- `.out` 文件中的**中文 KPI 报告**由 Agnes 模型在读取真实调度结果后生成，非模板文本；
- `agh-verify-p0.out` 中模型**自报算法版本 `event-adaptive-hga-1.0.0`、随机种子 20260916**，与 `algorithm-service/app/__init__.py:5` 的算法版本常量一致，说明模型确实读取并理解了系统返回；
- `agh-verify-2` 中模型基于对比结果给出「零扰动、无需发布」的处置结论；`agh-verify-3b` 中模型主动发现 EVT-002 未消费、PV-002 未发布——均为模型参与核心决策判断的直接证据；
- 审批场景下模型遵守「提交评审 → 停下请人工 → 审批 → 发布」三段式，未越权自动发布。
