# 02 技术信息

## 1. AGH 的作用

本作品以 **AGH（Agnes Harness）** 为智能体运行底座：

- 所有大模型调用只经由 Agnes 模型，AGH 负责任务编排、工具调度、审批拦截与会话账本记录；
- AGH 源码副本位于 `agh-integration/agnes-harness/`（上游 `github.com/AgnesAI-Labs/agnes-harness`，Apache-2.0，要求 Node ≥ 24.10，入口 `packages/cli/dist/local/agnes.mjs`，`serve` 子命令在 4177 端口启动工作台）；
- 自研 AGH 工具插件 `agh-integration/fjsp-tools/`（包名 `@fjsp/fjsp-tools`，单文件 `index.mjs`）把业务系统能力封装为 14 个 `fjsp_*` 工具供模型调用；
- 方法论 Skill `agh-integration/skills/fjsp-dispatch/SKILL.md` 约束智能体行为：基线流程、扰动处置流程、错误码处理，且只准使用 `fjsp_*` 工具；
- 端到端验证驱动 `agh-integration/driver/fjsp-agent.mts` 通过 AGH Node SDK 直连 daemon，发中文指令、程序化批准写工具审批、账本事件落盘 jsonl，形成可复核的执行证据。

### 模型参与的核心环节

1. **基线排程决策**：接收「完成基线排程并发布」等自然语言指令，自主编排看板查询 → 创建基线 → 轮询任务状态 → 发布的完整链路；
2. **扰动处置**：针对设备故障 / 紧急插单事件，选择局部或完全重调度策略并解释依据；
3. **方案对比解释**：读取多方案 KPI，输出中文对比报告与处置结论（如「故障落在空闲窗口、零扰动、无需发布」），并能主动发现未消费事件、未发布方案等异常状态；
4. **审批流人机协同**：写操作触发审批时主动停下请人工确认，按「提交评审 → 人工审批 → 发布」三段式推进高风险操作。

## 5. 专业软件 / 仿真环境

- **AGH（Agnes Harness）**：智能体运行底座，4177 端口工作台，承担模型调用、工具编排、审批与账本；
- **PostgreSQL 16**（Docker Compose 单容器）：业务持久化与审计存储；
- **调度仿真环境**：`algorithm-service` 即仿真内核，对 FJSP 实例求解并输出甘特/KPI；扰动事件（故障、插单）驱动重调度仿真；
- 辅助工具：`scripts/perf-baseline.sh`（7 条核心 SQL 的 EXPLAIN ANALYZE 性能基线）、`scripts/collect-evidence.sh。

## 6. API / 设备接口

### 6.1 AGH 工具接口（`fjsp_*` 14 个，HTTP 调业务服务）

工具调用携带 JWT 登录令牌、`Idempotency-Key` 幂等键、审计头 `X-Source: agh`。审批策略四级：

| 级别 | 含义 | 工具 |
|------|------|------|
| READ | 只读，免审批 | `fjsp_dashboard`（看板）、`fjsp_task_status`（任务状态轮询）、`fjsp_compare_plans`（方案对比）等 |
| WRITE | 写操作，需审批 | `fjsp_create_baseline`（基线排程）、`fjsp_report_breakdown`（故障上报）、`fjsp_report_rush_order`（紧急插单）、`fjsp_reschedule`（重调度）、`fjsp_submit_review`（提交评审）等 |
| HIGH_RISK | 高风险，需审批 | `fjsp_approve`（审批通过）、`fjsp_publish`（方案发布） |
| DESTRUCTIVE | 破坏性，需审批 | `fjsp_reset`（演示数据重置） |

> 各级别内工具的完整清单以 `agh-integration/fjsp-tools/index.mjs` 源码为准；发布路径固定为「提交评审 → 停下请人工 → 审批 → 发布」三段式人工确认。

### 6.2 业务 REST API

- 业务服务入口：`http://localhost:8081/api/v1`（默认前端入口 `http://127.0.0.1:8082/index.html?api=http://localhost:8081/api/v1`）；
- 认证：Spring Security + JWT；
- 横切机制：`Idempotency-Key` 幂等、乐观锁（并发发布返回 `E_VERSION_STALE`）、审计（`X-Source` / `X-AGH-Session-Id` 透传并落库）、SSE 事件推送；
- 错误码体系：见《研发附录》V1.1 API 契约与错误码章节（如 `E_DUPLICATE`、`E_VALIDATION`、`E_VERSION_STALE`）。

### 6.3 设备接口

本作品面向单车间管理层级，不直连物理设备；设备状态通过「故障上报 / 执行反馈」业务接口录入（对应 M-01…M-08 设备台账），未接入 PLC/OPC-UA 等工业协议。
